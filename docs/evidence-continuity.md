# Evidence continuity and account changes

Shared review matrices use current project membership for reading and editing. Mutations recheck the project role inside their write transaction. An extraction that finishes after the source is removed, the editor loses access, or the matrix is archived cannot commit. A newer manual correction is retained when an earlier extraction finishes.

A matrix with collaborator sources, collaborator changes, or collaborator audit events cannot be moved into a private workspace or another project. Removing a source does not remove this restriction. Create a new matrix from personally owned sources when a separate workspace is needed.

Matrix creation, title/column/project changes, source additions/removals, manual cell edits and AI extractions append audit events in the transaction that changes the matrix. A source-removal event retains its saved row evidence before the row is deleted. Project deletion adds a system detachment/archive event. These events record changes going forward; they do not reconstruct changes made before this audit was added. Deleting the matrix deletes its history too.

**Open as document** retains the comparison table and adds an evidence appendix grouped by paper and column. The appendix includes authors, title, year, DOI when available, the saved quotation, page and source basis. Abstracts, writer-entered text, unavailable pages and unverified results remain explicitly labeled. These are readable evidence references in the existing editor, not dynamic Word citation fields. CSV and evidence/audit JSON exports remain available separately.

When a project is deleted, matrices with collaborator contributions become read-only artifacts belonging to their creators. They retain saved cells, quoted excerpts, audit events, and bounded bibliographic summaries captured during detachment. They cannot fetch subsequent changes from any Library document. An unavailable summary stays explicitly unavailable; there is no live fallback. Creators can inspect, export, or delete these archives. Matrices containing only the creator's own work detach normally and remain editable. The matrix's **Evidence and audit** download includes its saved rows and decision history in JSON.

Research tasks remain personal outputs of the person who ran them; their creator can read them independently of project membership. Large results are stored as hashed objects and verified on read. Background workers use a separate object namespace for each lease. If a worker uploads after deletion or loses its lease before committing, it removes only its unreferenced object; an existing saved result is retained. Cancelling or deleting a task authorizes against its metadata, so an unavailable result object does not prevent those operations.

A background research job reserves credits once when it starts. If its user later joins or leaves a Team, the job still completes under that original reservation: usage metering, run counts, and any refund use the saved charge account. The current user's identity governs source access; task ownership and original account provenance remain unchanged. Subsequent jobs and interactive AI actions use the user's current account.

Systematic-review record limits follow the review owner's current account rather than the account recorded when the review was created. Collaborator imports use that same owner limit. Existing records remain retained after a plan change; the limit controls further additions. A missing or disabled owner's account does not confer a paid record limit.
